# LP4 local web, DAV, and discovery proof

LP4 adds a disposable, synthetic web and DAV boundary to the offline local
proof. It is an implementation-ready Compose rehearsal, not public-service,
external-client-interoperability, or production evidence. The machine-readable
contract is `release/lp4-local-web.json`.

## Boundaries

The `gulogulo-lp4-web` service serves the static web shell and same-origin API
on the internal `lp4-runtime` network. The network is IPv4/IPv6 dual stack and
has `internal: true`. The service uses `expose: 8080`; neither it nor the proof
client publishes a host port. Neither service mounts the Docker socket, uses
host networking, or runs privileged.

The proof runtime accepts one synthetic login identity. Its email and password
are required environment values generated by `scripts/lp4-compose-smoke.ts` at
run time. Compose and repository source contain no fallback credentials. The
login contract exercises the `__Host-gulogulo-session` cookie, authenticated
session lookup, tenant/user-scoped resources, CSRF-protected logout, and cookie
invalidation. It does not claim LDAP authentication interoperability.

The runtime seeds one deterministic calendar event and one deterministic
contact through the TypeScript CalDAV and CardDAV contracts. API results expose
opaque ETags and sync tokens under the authenticated tenant/user scope. The
same contracts reject cross-tenant actors and tokens in focused tests. A master
or monitoring role does not gain content access.

`lp4-dav-data` is mounted at `/var/lib/gulogulo/dav`. The runtime writes only a
synthetic continuity record containing scoped ETags and sync tokens, then
requires the exact record after restart. This proves named-volume attachment
and restart continuity for the local contract boundary. It is not a substitute
for a persistent production DAV adapter or backup/restore rehearsal.

Discovery covers:

- `/.well-known/caldav`;
- `/.well-known/carddav`;
- `/.well-known/autoconfig/mail/config-v1.1.xml`;
- `/.well-known/gulogulo/discovery.json`;
- the authenticated `/api/discovery` view.

Published destinations are HTTPS-only and tenant-bound. Discovery responses do
not contain credentials, internal datastore names, LDAP endpoints, PostgreSQL
endpoints, or session secrets.

## TypeScript migration

LP4 moves the web security/content/realtime/backup contracts plus CalDAV,
CardDAV, discovery, and their tests to strict-checked TypeScript:

- `src/web/security/` for sessions, cookies, CSRF, and authentication tests;
- `src/web/content/` for email sanitization, attachment policy, timezone
  handling, and their tests;
- `src/web/realtime/` for metadata-only event normalization and tests;
- `src/web/backup/` for the self-scoped metadata-only backup hook and tests;

- `src/dav/caldav/caldav-contract.ts`;
- `src/dav/carddav/carddav-store.ts` and `src/dav/carddav/index.ts`;
- `src/dav/discovery/index.ts`;
- the corresponding three `.test.ts` files.

The existing `.mjs` entry points in these migrated areas now contain only
import/export bridge statements and SPDX metadata. They remain temporary
compatibility entry points for callers that have not moved to TypeScript paths;
LP9 owns their removal.

## Deterministic checks

The local non-Docker checks are:

```text
node --experimental-strip-types src/dav/caldav/caldav-contract.test.ts
node --experimental-strip-types src/dav/carddav/carddav-store.test.ts
node --experimental-strip-types src/dav/discovery/index.test.ts
node --experimental-strip-types scripts/lp4-compose-audit.ts
```

The intended integrated npm entry points are `npm run test:lp4` and
`npm run test:lp4:docker`. The first runs the strict server/web/LP4 compiler
checks, all typed web and DAV tests, and the static audit. The second runs
`scripts/lp4-compose-smoke.ts`.

The live smoke builds the application image, starts `gulogulo-lp4-web`, runs
the internal proof client, inspects network/container/volume safety, restarts
the web service, and repeats the proof against the preserved DAV continuity
record. Docker is unavailable in the current Windows environment, so live
Compose evidence must run in GitHub Actions before LP4 can be called complete.

## Explicit non-claims

LP4 does not prove public DNS or ACME, Internet reachability, production TLS
termination, real LDAP authentication, external CalDAV/CardDAV clients,
production DAV persistence, backup/restore, capacity, or production readiness.
